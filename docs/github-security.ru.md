# Безопасность на GitHub: что настроено

English version: [github-security.md](github-security.md)

Здесь перечислены защиты репозитория, которые реально включены, что каждая ловит,
и что намеренно не включено, потому что платформа этого не поддерживает для такого
кода.

## Что включено

| Защита | Что делает | Где смотреть |
|---|---|---|
| **Dependabot alerts** | следит за графом зависимостей и сообщает об известных уязвимостях в используемых версиях | Security → Dependabot |
| **Dependabot security updates** | сам открывает PR, когда для уязвимой зависимости есть исправление | Pull requests с меткой `dependabot` |
| **Dependabot version updates** | раз в неделю обновляет GitHub Actions в workflow (`.github/dependabot.yml`) | Pull requests |
| **Secret scanning** | ищет в коммитах известные форматы токенов (GitHub, облачные ключи и т.п.) | Security → Secret scanning |
| **Push protection** | не даёт запушить найденный секрет, пока он не попал в историю | видно как отклонённый push |
| **Private vulnerability reporting** | исследователь открывает приватный advisory вместо публичного issue | Security → Advisories → Report |
| **OpenSSF Scorecard** | еженедельная проверка supply-chain: закреплены ли экшены, права токена, ревью, защита ветки; результат в SARIF | Security → Code scanning; `.github/workflows/scorecard.yml` |
| **Аттестация происхождения** | каждый файл релиза получает подписанное утверждение, каким workflow и из какого коммита он собран | `gh attestation verify` |
| **Контрольные суммы SHA-256** | `SHA256SUMS.txt` рядом с архивом релиза | страница Releases |

### Экшены закреплены по SHA коммита

Тег можно переписать, коммит — нет. Все `uses:` в репозитории указывают на полный
SHA, версия — в комментарии:

```yaml
- uses: actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1 # v7.0.1
```

Dependabot такие пины всё равно обновляет: он понимает комментарий `# vX.Y.Z`
и присылает PR с новым SHA. Это проверка «Pinned-Dependencies» в Scorecard.

## Как проверить релиз самому

```powershell
# 1. скачать архив и контрольные суммы, сравнить
Get-FileHash .\DesktopGroups-1.1.0.zip -Algorithm SHA256
Get-Content .\SHA256SUMS.txt

# 2. проверить аттестацию происхождения (нужен GitHub CLI 2.49+)
gh attestation verify .\DesktopGroups-1.1.0.zip --repo mikel38487/DesktopGroups
```

Успешная проверка означает, что файл произведён release-workflow этого
репозитория из конкретного коммита, а не загружен руками.

## Что НЕ включено и почему

| Чего нет | Причина |
|---|---|
| **CodeQL / code scanning для PowerShell** | CodeQL не поддерживает PowerShell. Файл `.cs` компилируется в рантайме через `Add-Type` и не имеет проекта, поэтому сборка для CodeQL означала бы отдельный шаг ради 200 строк. PowerShell закрыт PSScriptAnalyzer в CI, весь C# виден в одном файле. |
| **Проверка валидности секретов** | API принимает запрос, но настройка остаётся `disabled` для личного репозитория; поиск по провайдерским шаблонам при этом работает. |
| **Свои (не провайдерские) шаблоны секретов** | доступны организациям, не личному репозиторию. |
| **Защита ветки с обязательным ревью** | проект ведёт один человек: требовать ревью своих же PR — блокировать работу без пользы. Основные ворота — проверки в CI и в release-workflow (кодировка, smoke, локализация). |
| **Подписанные коммиты** | нужен постоянный GPG/SSH-ключ; для артефактов вместо этого аттестация происхождения, и она сильнее. |

## Что эти защиты уже поймали

- **Dependabot** сработал: два PR подняли `actions/checkout` и
  `actions/upload-artifact` с v4 до v7, оба слиты после зелёного CI.
- **Push protection** — в истории ничего не найдено, шаблонный поиск секретов
  тоже чист.
- **Scorecard** показывает posture, а не баги. Его балл — чек-лист, не оценка.

## Что можно добавить потом

- **Подпись Sigstore/cosign** для архива — альтернатива аттестации, без ключей,
  через OIDC GitHub.
- **SBOM** — `actions/dependency-submission` или SPDX-файл для архива; у проекта
  без пакетного менеджера SBOM — это в основном список файлов.
- **Значок OpenSSF Best Practices** — публичная самопроверка, полезный сигнал.
