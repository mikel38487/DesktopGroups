# Подпись кода через SignPath Foundation

English version: [code-signing.md](code-signing.md)

Это план, а не констатация: заявка **ещё не подана**. Здесь зафиксировано, что
требуется, что подготовить и как будет выглядеть интеграция после одобрения.

## Что даёт и чего не даёт

| Эффект | Реальность |
|---|---|
| Скрипты PowerShell запускаются при политике `RemoteSigned` по умолчанию, без `-ExecutionPolicy Bypass` | **да** — валидной подписи Authenticode достаточно |
| В свойствах подписанного файла видно имя издателя | да |
| SmartScreen перестаёт предупреждать | **не сразу**: валидная OV-подпись всё равно даёт предупреждение, пока не накопится репутация хеша или издателя |
| `.cmd`-запускалки получают подпись | **нет** — у Authenticode нет формата для `.cmd`/`.bat`; они остаются неподписанными и должны быть тонкими |

В справочнике артефактов SignPath есть элемент `<powershell-file>` для `.ps1`,
`.psm1`, `.psd1`, `.ps1xml` с директивой `<authenticode-sign>`. Ограничения на
метаданные (имя продукта и версия) относятся только к `<pe-file>`, поэтому проекту
из скриптов не нужен ресурс версии — это ровно наш случай.

## Условия допуска (по условиям SignPath Foundation)

Для бесплатной OSS-подписки:

- лицензия OSI без коммерческого двойного лицензирования — MIT ✓;
- нет проприетарных компонентов — всё в репозитории ✓;
- проект активно поддерживается ✓;
- **уже выпущен в том виде, который надо подписать** ✓ (v1.0.0 … v1.1.1);
- функциональность описана ✓ (README, `docs/guide.ru.md`).

Для бесплатного сертификата (SignPath Foundation становится издателем) дополнительно:

- подписывать только свой код и свои артефакты;
- **заявление о приватности** на странице проекта — добавлено в README;
- сообщать об изменениях в системе — программа меняет обои и позиции значков, это
  описано в README и `SECURITY.ru.md` ✓;
- дать возможность удаления ✓ (`uninstall.cmd`);
- **включённая MFA** на GitHub и в SignPath;
- объявленные роли ревью и утверждения;
- **раздел «Политика подписи кода»** с точной формулировкой
  «Free code signing provided by SignPath.io, certificate by SignPath Foundation» —
  добавлен в README.

## Заявка

1. Открыть <https://signpath.org/apply> и заполнить форму. Подготовить:
   - URL репозитория и короткое описание, что программа делает;
   - лицензию (MIT) и подтверждение, что проприетарных частей нет;
   - выпущенный артефакт, который надо подписать (ZIP из Releases);
   - ссылку на раздел политики подписи (якорь в README);
   - кто ведёт проект и кто утверждает релизы.
2. Дождаться ручного рассмотрения. Решение принимается вручную, и они берут на себя
   риск публикации под своим именем, поэтому молодой проект могут попросить
   вернуться, когда появится заметное использование. Слабое место честно одно:
   проект новый.
3. После одобрения: установить [SignPath GitHub App](https://github.com/apps/signpath)
   и связать репозиторий.

## Настройка после одобрения

1. **Организация** — одна на человека. В ней может быть несколько проектов:
   проект в SignPath — это один продукт или набор артефактов, которые подписываются
   вместе. Поэтому тот же путь используется для других open-source проектов: каждый
   заводится отдельным проектом и одобряется отдельно.
2. **Проект** — `DesktopGroups`.
3. **Политика подписи** — сертификат SignPath Foundation, только релизные сборки,
   **ручное утверждение каждого релиза**, доверенная система сборки GitHub.com.
4. **Конфигурация артефакта** — версионируемый XML со списком файлов:

```xml
<artifact-configuration xmlns="http://signpath.io/artifact-configuration">
  <zip-file>
    <powershell-file path="DesktopGroups.ps1">
      <authenticode-sign/>
    </powershell-file>
    <powershell-file path="lib\Engine.ps1">
      <authenticode-sign/>
    </powershell-file>
    <powershell-file path="lib\Strings.ps1">
      <authenticode-sign/>
    </powershell-file>
    <powershell-file path="tools\install.ps1">
      <authenticode-sign/>
    </powershell-file>
    <powershell-file path="tools\uninstall.ps1">
      <authenticode-sign/>
    </powershell-file>
  </zip-file>
</artifact-configuration>
```

5. **Секрет** — `SIGNPATH_API_TOKEN` в секретах репозитория (токен только с ролью
   отправки запроса на подпись).

## Что меняется в workflow

Между сборкой ZIP и публикацией появляется один шаг:

```yaml
- name: Sign the archive
  uses: signpath/github-action-submit-signing-request@<sha> # v3
  with:
    api-token: ${{ secrets.SIGNPATH_API_TOKEN }}
    organization-id: <org-id>
    project-slug: desktopgroups
    signing-policy-slug: release-signing
    artifact-configuration-slug: zip-with-scripts
    github-artifact-id: ${{ steps.build.outputs.artifact-id }}
    wait-for-completion: true
    output-artifact-directory: dist-signed
```

ZIP надо выгружать через `actions/upload-artifact` (v4 или новее): экшен работает
с идентификаторами артефактов. Все задания — на GitHub-hosted раннерах. После
подписи workflow заново считает `SHA256SUMS.txt` и аттестацию для **подписанного**
архива.

## Что меняется для пользователя

- В README убираем обход политики запуска, оставляем предупреждение, что SmartScreen
  может ругаться, пока не накопится репутация.
- `install.cmd` / `DesktopGroups.cmd`: `-ExecutionPolicy Bypass` можно оставить для
  совместимости, но с подписанными скриптами он уже не нужен.
- В `SECURITY.ru.md` — строка о том, кто подписал релиз и как проверить
  (`Get-AuthenticodeSignature`).

## Как переиспользовать в других проектах

- Одна **организация** SignPath покрывает все ваши репозитории.
- Каждый продукт — отдельный **проект** со своей политикой подписи и конфигурацией
  артефакта; каждый open-source проект проходит собственное рассмотрение.
- Сертификат остаётся сертификатом SignPath Foundation, поэтому правила одинаковы
  везде: только свой код, заявление о приватности, роли ревью, ручное утверждение
  релизов.
- В настройке нет ничего специфичного для PowerShell: для проекта на C# или Go
  конфигурация артефакта просто использует `<pe-file>` с ограничениями метаданных.

## Стоимость и обязательства

- Для open-source проектов платы нет.
- Ручное утверждение каждого релиза — публиковать без участия человека нельзя.
- Проект могут приостановить или отозвать сертификат при нарушении кодекса поведения.
