# Ревью локализации DesktopGroups 1.1.0

- Проект: `F:\AI\DesktopGroups`, ветка `main`, ревью по коммиту `c0f05a1`.
- Ветка за время проверки ушла вперёд (HEAD `ae623f0`), но файлы локализации не менялись:
  `git diff --stat c0f05a1 -- DesktopGroups.ps1 lib/Strings.ps1 lib/Engine.ps1 tests/i18n.ps1` — пусто.
  Поэтому все выводы относятся и к `c0f05a1`, и к текущему HEAD.
- Объём: `lib\Strings.ps1`, `DesktopGroups.ps1`, `lib\Engine.ps1`, `tests\i18n.ps1`, `tests\check-encoding.ps1`.
- Код не правился. Создан только этот файл. Пользовательский `config.json` не изменялся
  (SHA256 до и после: `AB418FD9…F4F9C1F2`), раскладка и обои не применялись.
- Стенд: Windows 11 26100, ru-RU, масштаб 96 DPI, `powershell.exe` 5.1.26100.9711 и `pwsh` 7.6.9.
- Метод: чтение кода, грепы литералов, прогон тестов под двумя хостами, живые замеры
  `TextRenderer::MeasureText` и GDI+, четыре запуска GUI с копией конфига в `%TEMP%\dg-review`,
  переключение языка через комбобокс, скриншот с увеличением.

## Находки

### I18N-01 — непереведённые сообщения об ошибках из движка (major)

- **Где:** `lib\Engine.ps1:16, 402, 569, 574, 578, 620, 629`; показ пользователю —
  `DesktopGroups.ps1:776`, `841-842`, `881`, `891`, `961`.
- **Суть:** движок бросает русские литералы. Обработчики кладут `$_.Exception.Message`
  в MessageBox и в статус без перевода. Пользователь с английским интерфейсом получает
  русский текст в английском окне; для .NET-исключений текст вообще приходит на языке ОС.
- **Как проверил:**
  ```powershell
  Select-String -Path lib\Engine.ps1 -Pattern 'throw ' -Encoding utf8
  # Engine.ps1:402: throw ('файл фона слишком большой: {0} МБ' -f ...)
  # Engine.ps1:569: throw 'Не найден список значков рабочего стола (SysListView32)'
  # … всего 7 строк, все по-русски
  ```
  Живая проверка канала: подсунул в `Get-BackgroundImage` файл, который не является
  картинкой:
  ```
  GDI+ message: Исключение при вызове "FromStream" с аргументами "1": "Parameter is not valid."
  ```
  То есть в MessageBox уходит текст, не зависящий от языка интерфейса, — ветка
  `DesktopGroups.ps1:775-776` показывает его как есть.
- **Исправление:** завести ключи `err.*` в `Strings.ps1` и бросать `(T 'err.x' @(...))`.
  Учесть порядок подключения: `DesktopGroups.ps1:17-18` сначала грузит `Engine.ps1`,
  потом `Strings.ps1`, поэтому для `throw` на строке 16 (проверка разрядности) `T` ещё
  не определена — либо поменять порядок, либо перенести эту проверку в `DesktopGroups.ps1`
  после `Strings.ps1`.

### I18N-02 — неверный путь в меню Windows (major)

- **Где:** `lib\Strings.ps1:81` (`msg.autoArrange`, ru).
- **Суть:** «правый клик по столу → Упорядочить значки → снять «Упорядочить автоматически»».
  Пункта «Упорядочить значки» в русской оболочке нет, а пункт называется
  «Упорядочить значки автоматически». Английская версия той же строки (`Strings.ps1:184`)
  называет корректный путь: `right-click the desktop → View → uncheck «Auto arrange icons»`.
  Русский и английский тексты дают разные пути к одному и тому же пункту — значит,
  один из них неверен; по ресурсам оболочки неверен русский.
- **Как проверил:** вытащил строки из ресурсов оболочки этой машины:
  ```powershell
  $p = [Text.Encoding]::Unicode.GetString([IO.File]::ReadAllBytes("$env:SystemRoot\System32\ru-RU\shell32.dll.mui")) -split "`0"
  $p | Where-Object { $_ -match 'Упорядочить значки|Упорядочить автоматически' } | Select-Object -Unique
  # …&Упорядочить значки автоматически&Выровнять значки по сетке…
  ($p | Where-Object { $_ -eq 'Упорядочить значки' }).Count   # 0
  ```
- **Исправление:** «правый клик по столу → Вид → снять «Упорядочить значки автоматически»».
  Формулировку лучше сделать устойчивой к версиям ОС: «→ Вид → отключить автоматическое
  упорядочивание значков (в Windows 11 — «Упорядочить значки автоматически»)».

### I18N-03 — служебная группа переименовывается только комбобоксом (major)

- **Где:** `DesktopGroups.ps1:402-420` (`Set-InterfaceLanguage`), вызовы языка —
  `DesktopGroups.ps1:53` (`-Lang`), `105-107` (config.json).
- **Суть:** переименование «Прочее» ↔ «Misc» живёт только в `Set-InterfaceLanguage`,
  а он вызывается исключительно из обработчика комбобокса (`422-429`). Если язык пришёл
  из `-Lang` или из `config.json`, интерфейс переключается, а служебная группа остаётся
  на прежнем языке. Ровно это состояние у пользователя в репозитории: `config.json`
  содержит `"language": "en"`, а группа называется «Прочее».
- **Как проверил:** три запуска на копии конфига (`%TEMP%\dg-review`), чтение дерева UIA.
  1. `config language=en`, без `-Lang` → заголовок `DesktopGroups 1.1.0 — desktop shortcut groups`,
     в списке `Прочее  (2)`.
  2. Переключение комбобоксом ru→en → в списке появилось `Misc  (2)`, в конфиге
     `language=en`; то есть механизм работает только на этом пути.
  3. `config language=ru` + группа «Прочее», запуск с `-Lang en` → заголовок английский,
     `-Lang` перебил конфиг, но в списке осталось `Прочее  (2)`; после закрытия в конфиге
     `language=en`, группа по-прежнему «Прочее».
- **Исправление:** вынести переименование в `Update-Language` (или отдельную
  `Sync-OtherGroupName`) и вызывать после любого определения языка, включая `Import-Config`
  и `-Lang`. Переименовывать по обоим известным именам («Прочее» и «Misc»): сейчас
  состояние «английский интерфейс + Прочее» не исправляется даже повторным выбором языка —
  обработчик выходит по `if ($code -eq $script:UiLanguage) { return }` (`427`).

### I18N-04 — обрезанная последняя строка справки (minor)

- **Где:** `DesktopGroups.ps1:346-350` (`$lblHelp` 396×122, Segoe UI 8), текст —
  `lib\Strings.ps1:38-48` и `141-151`.
- **Суть:** в блок из 122 px не влезают 9 строк; нижняя строка («the icons and draws the
  frames with labels.» / «значки и рисует рамки с подписями.») срезана примерно наполовину.
  Дефект общий для обоих языков: и ru, и en дают ровно 9 строк при ширине 396.
- **Как проверил:** скриншот окна → вырезка области справки с увеличением ×3:
  последняя строка видна только верхней половиной. Числа:
  `Font.Height` Segoe UI 8 = 15 px; GDI+ `MeasureString` при ширине 396 = **129 px** (ru и en);
  контроль — 122 px. `TextRenderer::MeasureText` даёт 117 px, то есть занижает, — именно
  поэтому дефект не поймали замером при разработке.
- **Исправление:** высота 140 (или `y=182 → 176` при высоте 128). Проверять замером
  GDI+ `MeasureString(text, font, 396)`, а не `MeasureText`.

### I18N-05 — диалог сохранения обоев не локализован (minor)

- **Где:** `DesktopGroups.ps1:852-854`.
- **Суть:** `$dlg.Filter = 'PNG|*.png'` — литерал, `Title` не задан, поэтому диалог
  показывает системный заголовок («Сохранить как» на русской Windows) независимо от
  языка интерфейса. Рядом `OpenFileDialog` локализован через `T` (`764-765`):
  часть диалогов на языке приложения, часть — на языке ОС.
- **Как проверил:** `Select-String -Pattern '\.Title\s*=|\.Filter\s*='` — строки 764, 765
  через `T`; 853 — литерал; `Title` для `SaveFileDialog` отсутствует.
- **Исправление:** `$dlg.Title = T 'dlg.saveTitle'`, `$dlg.Filter = T 'dlg.pngFilter'`
  (`PNG|*.png|Все файлы|*.*` / `PNG|*.png|All files|*.*`).

### I18N-08 — «ярлыки» и «значки» об одном и том же (minor)

- **Где:** `lib\Strings.ps1:34` (`lbl.previewEmpty` = «Групп с ярлыками нет»), `41`
  (справка: «читает ярлыки, папки и файлы») против `80` («Нет групп со значками»), `25`,
  `32`, `33` и подписей кнопок («Добавить значки…», «Убрать из группы»).
- **Суть:** в интерфейсе принят термин «значок», в двух строках — «ярлык». В русском это
  разные объекты (ярлык — файл `.lnk`), пользователь видит оба термина. Английские версии
  последовательны: `No groups with icons`, `reads shortcuts, folders and files`.
- **Как проверил:** выгрузка всех ключей и чтение ru/en пар.
- **Исправление:** `lbl.previewEmpty` → «Групп со значками нет»; в справке п. 1 —
  «читает значки, папки и файлы» (термин `shortcut` оставить только там, где речь
  действительно о типе файла, как в en).

### I18N-09 — `Get-GroupName` по умолчанию берёт язык системы (minor)

- **Где:** `lib\Engine.ps1:50-60` (ветка «язык не задан» → `Get-DefaultLanguage`).
- **Суть:** весь остальной интерфейс по умолчанию использует `$script:UiLanguage`, а эта
  функция — язык ОС. Пока все вызовы передают `-Lang` (`DesktopGroups.ps1:590, 915`),
  поэтому дефект не проявляется, но любой новый вызов без `-Lang` даст русские названия
  групп в английском интерфейсе.
- **Как проверил:**
  ```
  Set-Language 'en'
  T group.other                    = Misc
  Get-GroupName -Id 'games'        = Игры
  Get-GroupName -Id 'games' -Lang 'en' = Games
  ```
- **Исправление:** если `$Lang` пуст — брать `$script:UiLanguage`, если он определён,
  иначе `Get-DefaultLanguage`; зафиксировать тестом.

### I18N-11 — английская типографика кавычек (nit)

### I18N-12 — «настройки», «конфиг», «Settings» об одном файле (nit)

### I18N-14 — две копии определения языка (nit)

- **Где:** `lib\Strings.ps1:213-221` (`Get-SystemLanguage`) и `lib\Engine.ps1:42-48`
  (`Get-DefaultLanguage`) — идентичный код в двух файлах.
- **Суть:** два источника истины. Сейчас результаты совпадают (проверено на 5.1 и 7),
  но разойтись они могут молча. Отдельно: `InstalledUICulture` — язык установки, а не
  язык интерфейса ОС. Если на русскую Windows поставлен английский языковой пакет, обе
  функции вернут `ru`, хотя интерфейс ОС английский, а «Корзина» на столе называется
  `Recycle Bin` — тогда `Engine.ps1:144-145` будет искать несуществующий элемент.
- **Как проверил:** прогон обеих функций под двумя хостами (ниже, раздел «Проверено»);
  `Get-WinUILanguageOverride` = пусто, `Get-WinUserLanguageList[0]` = `ru`,
  `InstalledUICulture` = `ru-RU` — на этой машине расхождения нет.
- **Исправление:** оставить одну функцию (например, в `Strings.ps1`), а в `Engine.ps1`
  вызывать её. Для языка отображения — `(Get-WinUserLanguageList)[0]` с откатом на
  `InstalledUICulture`.

### I18N-15 — тест не ловит основные классы дефектов (nit)

- **Где:** `tests\i18n.ps1:37-46`.
- **Суть:** тест проверяет совпадение наборов ключей, пустые строки, подстановку нуля и
  названия групп. Он не проверяет: (а) непереведённые литералы в `.ps1` — именно они дали
  I18N-01, I18N-05, I18N-06; (б) паритет `{n}` между ru и en; (в) число аргументов на
  местах вызова `T`; (г) ключи в `Engine.ps1` — сканируется только `DesktopGroups.ps1`.
- **Как проверил:** чтение теста; отдельный прогон паритета и аргументов (раздел
  «Проверено, дефектов нет») — дефектов не нашёл, но тест их и не искал.
- **Исправление:** добавить в `tests\i18n.ps1` четыре проверки: греп кириллицы вне
  `Strings.ps1`; сравнение наборов `{n}`; подсчёт аргументов в вызовах `T`; скан
  `Engine.ps1` на ключи.

### I18N-16 — длинное имя группы обрежется в заголовке панели (nit)

- **Где:** `DesktopGroups.ps1:456` (`grpItems.Text = T 'grp.itemsOf' @($g.name)`),
  ограничение имени — `DesktopGroups.ps1:119` (200 символов).
- **Суть:** `GroupBox` не переносит и не сокращает заголовок. При имени в 30 символов
  запас ещё есть (ru 288 px при ширине 360), но допустимые 200 символов дадут обрезку.
  Это не про перевод, а про то, что подпись собирается из пользовательских данных.
