## Блокеры

### F-01. Имена файлов с расширением не совпадают с тем, что показывает Explorer при стандартном `HideFileExt=1`

- **Severity:** blocker.
- **Файл:** `lib/Engine.ps1:40-41` (расширение срезается только у `.lnk`/`.url`), `lib/Engine.ps1:484-497` (цели в `Invoke-DesktopLayout` строятся по точному имени).
- **Суть:** `Get-DesktopItems` для обычных файлов берёт `$f.Name` целиком (`app.exe`), а desktop-ListView отдаёт **display name** оболочки. При стандартной настройке Windows «Скрывать расширения для известных типов файлов» (`HideFileExt=1`) это `app`, без `.exe`. План содержит `app.exe`, `$before` — `app`; совпадения нет, файл считается «чужим» и уезжает в колонку fallback, а его ячейка остаётся пустой. Комментарий в коде («у файлов расширение не скрывается») неверен для настроек по умолчанию.
- **Как воспроизвёл:**
  - На машине ревью `HideFileExt=0`: `Get-DesktopItems` → `Qwen-Code-Desktop-x64.exe`, `Read-ViewItems` → `Qwen-Code-Desktop-x64.exe`; имена совпадают.
  - Временно `HideFileExt=1`: `SHGetFileInfo(SHGFI_DISPLAYNAME)` для `test.exe` → `test`, для `test.txt` → `test`; вернул `0`. Desktop-ListView в уже запущенном Explorer не перечитал подписи без перезапуска, но новый значок/новый сеанс Explorer использует именно display name.
  - Мок: план `app.exe`, `tool.exe`, в ListView — `app`, `tool`:
    ```text
    placed=4 passes=2 mismatches=0 unknown=[app,tool]
    final [app] x=1762 y=202
    final [tool] x=1762 y=302
    ```
- **Ожидалось:** скан и применение используют одну модель имён; `app.exe` встаёт в свою ячейку.
- **Фактически:** файл не встаёт в план, а переносится в правую колонку; `mismatches=0`, то есть проблема не диагностируется.
- **Исправление:** в `Get-DesktopItems` получать display name через `SHGetFileInfo(..., SHGFI_DISPLAYNAME)` для всех элементов; либо в `Invoke-DesktopLayout` строить цели и по полному имени, и по `BaseName` (как это уже делает `Resolve-GroupItems`); либо явно учитывать `HideFileExt`. Добавить регрессионный тест с `HideFileExt=1`.

**Статус:** открыто (в рабочем дереве логика не менялась).

### F-02. «Сканировать стол» очищает группы, а закрытие окна сохраняет пустой конфиг

- **Severity:** blocker.
- **Файл:** `DesktopGroups.ps1:340-341` (`$script:Groups.Clear()` без подтверждения), `DesktopGroups.ps1:603` (`Add_FormClosing` всегда вызывает `Save-Config`).
- **Суть:** нажатие «Сканировать стол» сбрасывает все группы. Само по себе это ещё не потеря: конфиг не сохраняется сразу, но при закрытии окна `FormClosing` пишет текущее (пустое) состояние. Пользователь, который просканировал стол «чтобы обновить список» и закрыл программу, теряет все назначения групп. Резервные копии хранят только позиции значков, не конфиг.
- **Как воспроизвёл:** извлёк реальный обработчик `$btnScan.Add_Click` из AST, подменил `Get-DesktopItems`/`Update-*`, вызвал его:
  ```text
  before scan: groups=2 config-groups=2
  after scan: groups=0 status=[Найдено значков: 2. ...]
  after close: config-groups=0 -> назначения групп потеряны
  ```
- **Ожидалось:** скан обновляет список значков, не трогая группы; либо перед сбросом — подтверждение и сохранение `config.before-scan-*.json`.
- **Фактически:** молчаливый сброс + запись пустого конфига при закрытии.
- **Исправление:** убрать `$script:Groups.Clear()` из сканирования; после сканирования вызывать `Resolve-GroupItems` для существующих групп. Если сброс нужен — `MessageBox` Yes/No и бэкап конфига перед очисткой.

**Статус:** открыто (в рабочем дереве обработчик не менялся).

### F-03. Обои всегда 1920×1080; на экранах другого размера рамки не совпадают со значками

- **Severity:** blocker (на экранах ≠ 1920×1080; на машине ревью 1920×1080 не проявляется).
- **Файл:** `lib/Engine.ps1:276` (`Save-Wallpaper` по умолчанию `Width=1920, Height=1080`), `DesktopGroups.ps1:539` (вызов без размеров).
- **Суть:** раскладка считается в координатах экрана, а холст обоев фиксирован 1920×1080 и применяется с `WallpaperStyle=10` (Fill), то есть масштабируется под физический экран. На 2560×1440 или 1366×768 рамки уезжают относительно значков. README при этом обещает «frames always match the grid».
- **Как воспроизвёл:**
  ```text
  default: 1920x1080
  explicit 1366: 1366x768
  explicit 2560: 2560x1440
  2560 layout: max block x=2142; default wallpaper 1920 ->
    frame x=1606.5 vs icon x=2142
  ```
  Для 1366: блок `x=926` при масштабе 1366/1920 даёт рамку ≈659 при значке 926 (расчёт).
- **Ожидалось:** холст равен размеру экрана (в тех же координатах, в которых ставятся значки), либо раскладка масштабируется вместе с холстом.
- **Фактически:** на 1920×1080 всё совпадает; на других разрешениях — нет.
- **Исправление:** передавать размеры экрана в `Save-Wallpaper` (в рабочем дереве для «Применить» уже сделано: `DesktopGroups.ps1:609`), но обязательно в **физических** пикселях с учётом DPI (см. F-09). Для кнопки «Сохранить обои в файл…» (`DesktopGroups.ps1:573` в `64125fe`) размеры тоже нужно передавать.

**Статус:** частично исправлено в рабочем дереве: «Применить» передаёт `$script:Screen.width/height`; кнопка сохранения — всё ещё без размеров; DPI не учтён.

## Мажорные

### F-04. Группа больше ~96 значков даёт блок шире экрана, `overflow=False`, значки уходят за край

- **Severity:** major (для группы 200 — фактически blocker).
- **Файл:** `lib/Engine.ps1:175-187` (перебор `rows` 1..4 и `cols > 6`), `lib/Engine.ps1:192-197` (fallback), `lib/Engine.ps1:199-201` (проверяется только высота).
- **Суть:** для `n > 24` все кандидаты с `rows=1..4` дают `cols > 6`; срабатывает fallback `rows=4, cols=ceil(n/4)`. Для 200 значков это 50 колонок, ширина 3800 px. Горизонтального переполнения в коде нет: `overflow` выставляется только по `workHeight`, поэтому предупреждения не будет. `Save-Wallpaper` рисует рамку, обрезая её холстом; `Invoke-DesktopLayout` ставит значки на x=3738.
- **Как воспроизвёл:**
  ```text
  === 200 items ===
  blocks=1 overflow=False plan=200
  [G200] x=14 y=202 w=3800 h=400 cols=50 rows=4 items=200
  maxCellX=3738
  ```
  `Save-Wallpaper` для этого layout создаёт файл 1920×1080 (рамка обрезана).
- **Ожидалось:** блок влезает в экран, либо `overflow=True` и явное предупреждение; группа дробится на несколько блоков.
- **Фактически:** 50-колоночный блок, значки за пределами экрана, `overflow=False`.
- **Исправление:** ограничивать `cols` через `maxCols = floor((width-2*margin)/stepX)` и `rows` через доступную высоту; при `n > maxCols*maxRows` — резать группу на несколько блоков; выставлять `overflow` и по ширине. В рабочем дереве уже есть ограничение `maxCols`; для 200 получается 24×9 и `overflow=True`, но 9-й ряд всё равно уходит под панель задач, а горизонтальное переполнение по-прежнему не флагуется.

**Статус:** частично исправлено в рабочем дереве (ширина ограничена, вертикальное переполнение осталось).

### F-05. Всё, чего нет в плане, сваливается в фиксированную колонку x=1762; она уходит за экран

- **Severity:** major.
- **Файл:** `lib/Engine.ps1:488` (`$fallbackX = $grid.margin + 23 * $grid.stepX`), `lib/Engine.ps1:491-497` (неизвестные получают `y = top + stepY*row` без переноса).
- **Суть:** «чужие» значки — виртуальные («Этот компьютер», «Сеть»), новые файлы, переименованные ярлыки, значки, убранные из группы, — не остаются на месте, а переносятся в одну колонку. На 1920 при `stepX=76` это x=1762; после 8 значков `y` уходит за рабочую область (1032) и за экран. На 1366 x=1762 вообще за экраном. `mismatches=0`, потому что fallback-цель считается достигнутой.
- **Как воспроизвёл (моки):**
  ```text
  12 unknown icons: placed=17 passes=2 mismatches=0
    This PC 1  x=1762 y=202
    ...
    This PC 8  x=1762 y=902
    This PC 9  x=1762 y=1002
    This PC 10 x=1762 y=1102
    This PC 12 x=1762 y=1302
  1366 + unknown: This PC x=1762 (ширина 1366)
  переименован a2 -> a2 renamed: x=1762 y=202, unknown=[a2 renamed]
  убран из группы a2: x=1762 y=202
  два свободных: loose1 x=1762 y=202, loose2 x=1762 y=302
  ```
- **Ожидалось:** свободные/неизвестные значки остаются там, где были, либо размещаются в гарантированно видимой свободной области; о них сообщается.
- **Фактически:** принудительный перенос в фиксированную колонку, часто за экран; проблема не отражается в `mismatches`.
- **Исправление:** не двигать значки, которых нет в плане (или двигать только по явной команде); если двигать — вычислять свободную область от `workWidth/workHeight`, переносить по строкам/колонкам и проверять границы. `fallbackX` не должен быть константой `23 * stepX`.

**Статус:** открыто.

### F-06. Одинаковые отображаемые имена (свой + общий рабочий стол) схлопываются в одну цель; два значка стоят друг на друге

- **Severity:** major.
- **Файл:** `lib/Engine.ps1:43-45` (дедупликация по `$name.ToLower()`), `lib/Engine.ps1:484-497` (цели и позиции — по имени).
- **Суть:** если в `C:\Users\<user>\Desktop` и `C:\Users\Public\Desktop` есть файлы с одинаковым отображаемым именем, Explorer обычно показывает оба значка. `Get-DesktopItems` оставляет только первый, а `Invoke-DesktopLayout` получает из ListView два элемента с одинаковым `name` и ставит оба в одну и ту же ячейку. `mismatches=0`, `placed` считает цели, а не значки.
- **Как воспроизвёл (моки):** два элемента `a1`, план содержит `a1` один раз:
  ```text
  duplicate name a1: placed=5 passes=2 mismatches=0
    final a1 idx=0 x=14 y=202
    final a1 idx=1 x=14 y=202
  ```
  Для шести значков `placed=5`; один значок не виден.
- **Ожидалось:** оба значка получают разные ячейки, либо приложение явно сообщает о неоднозначности и не трогает дубликат.
- **Фактически:** наложение; пользователь теряет один значок из виду.
- **Исправление:** не дедуплицировать по имени в `Get-DesktopItems` (или дедуплицировать только для отображения); ключом плана делать `path`/индекс, а не имя; при совпадении имён — разводить по разным ячейкам и предупреждать.

**Статус:** открыто.

### F-07. Битый `config.json` молча перезаписывается предложенными группами

**Статус:** исправлено в рабочем дереве (переименование битого файла); сообщение пользователю всё ещё не выводится.

### F-08. Шаг сетки всегда спрашивается для крупных значков; при мелких/средних значках раскладка неверна

- **Severity:** major.
- **Файл:** `lib/Engine.ps1:458-465` (`LVM_GETITEMSPACING` с `wParam=0`).
- **Суть:** `LVM_GETITEMSPACING` с `wParam=0` возвращает spacing для large icon view, с `wParam=1` — для small icon view. Код всегда передаёт `0` и не смотрит текущий стиль ListView. Если пользователь переключил рабочий стол на мелкие значки (`LVS_SMALLICON`), фактическая сетка другая, а программа строит раскладку по крупной.
- **Как воспроизвёл:** прочитал стиль ListView и оба варианта spacing:
  ```text
  style=0x56003A40 type=0 (ICON)
  spacing wParam=0 -> 76x100
  spacing wParam=1 -> 96x49
  Get-ViewGridStep -> 76x100
  ```
  Сейчас стиль ICON, поэтому код прав. При переключении на мелкие значки стиль станет SMALLICON, фактический шаг — 96×49, а код продолжит брать 76×100.
- **Ожидалось:** шаг соответствует текущему режиму отображения.
- **Фактически:** для мелких/средних значков сетка не совпадает; значки и рамки разъезжаются.
- **Исправление:** прочитать `GWL_STYLE`, взять `style & LVS_TYPEMASK`; для `LVS_SMALLICON` передавать `wParam=1`; либо измерять реальные позиции соседних значков. Добавить тест на оба режима.

**Статус:** открыто.

### F-09. Процесс DPI-unaware: на масштабировании экранные метрики виртуальные, а ListView/обои — физические

- **Severity:** major.
- **Файл:** `lib/Engine.ps1:241-248` (`Screen.Bounds/WorkingArea`), `lib/Engine.ps1:276` (холст 1920×1080), `DesktopGroups.ps1:539`.
- **Суть:** и `powershell.exe` 5.1, и `pwsh` 7.6 в этой конфигурации имеют `GetProcessDpiAwareness = 0` (unaware). При масштабе 125/150% `Screen.Bounds` виртуализуется (например, 1707×960 на физических 2560×1440), а `LVM_GETITEMSPACING` приходит из DPI-aware Explorer в физических пикселях. Раскладка смешивает виртуальные и физические координаты; обои 1920×1080 растягиваются. На 96 DPI (машина ревью) не проявляется.
- **Как воспроизвёл:**
  ```text
  PS=5.1.26100.9711 hr=0 awareness=0 (0=unaware,1=system,2=per-monitor)
  PS=7.6.9 Core      hr=0 awareness=0
  Screen bounds=1920x1080 work=1920x1032
  ```
  Плюс расчёт F-03: layout 2560 при холсте 1920 даёт рамку 1606.5 против значка 2142.
- **Ожидалось:** процесс объявляет DPI-awareness (system/per-monitor) до создания WinForms; размеры экрана и холста берутся в физических пикселях; координаты ListView и обоев в одной системе.
- **Фактически:** на масштабированных ноутбуках раскладка занимает не весь экран и/или рамки не совпадают.
- **Исправление:** вызвать `SetProcessDpiAwarenessContext(PER_MONITOR_AWARE_V2)` до `Application.EnableVisualStyles`/создания формы; для холста использовать физический размер (`EnumDisplaySettings`/`GetSystemMetricsForDpi`), а не `Screen.Bounds`; проверить на 125% и 150%.

**Статус:** открыто.

### F-10. Некорректный цвет в конфиге проходит загрузку, затем роняет отрисовку предпросмотра

- **Severity:** major.
- **Файл:** `DesktopGroups.ps1:36-45` (цвет читается как есть), `DesktopGroups.ps1:318` (`Convert-HexColor` в обработчике `Paint`), `lib/Engine.ps1:252-261` (ожидает 6 hex-цифр).
- **Суть:** `Load-Config` не валидирует `color`. Значение `red` или `#FFF` загружается, а `Convert-HexColor` бросает исключение. В `Paint` нет `try/catch`, поэтому исключение уходит в WinForms: пустой предпросмотр и/или повторяющиеся диалоги ошибки при каждой перерисовке.
- **Как воспроизвёл:** конфиг `{"groups":[{"name":"G","color":"red","items":["Steam"]}]}`:
  ```text
  7) bad color -> Load=True color=red
     Convert-HexColor THROWS: Exception calling "ToInt32" ... "Could not find any recognizable digits."
  ```
  `#FFF` даёт `Substring` out of range.
- **Ожидалось:** невалидный цвет заменяется цветом из палитры при загрузке; `Paint` не бросает наружу.

## Приложение: что проверено, претензий нет

- Обычная сходимость: 5 значков, `passes=2`, все на целевых позициях, `mismatches=0`.
- Сдвиг соседа при занятой ячейке (мок «push»): сходится за 2 прохода, 0 расхождений.
- Цикл применения ограничен 10 проходами; бесконечного цикла нет (при игнорировании позиций — 10 проходов, 2 с, 5 расхождений).
- Формы блоков для 1/2/5/24/25/47 значков разумны; 0-значковая группа пропускается; 25 и 47 влезают в 1920.
- 30 групп по 3 значка: вертикальное переполнение корректно помечается `overflow=True`.
- 8 групп по 6 значков на 1366×768: помещаются, `overflow=False`.
- `Save-Wallpaper`: создаёт каталог, пишет PNG, корректно работает с кириллическим путём и пробелами; размеры, заданные явно, соблюдаются.
- Конфиг: UTF-8 с BOM пишется и читается в 5.1 и 7; BOM-less UTF-8 и UTF-16 с BOM читаются; кириллица сохраняется; одноэлементный массив `items` остаётся массивом.
- `Resolve-GroupItems`: точное имя, регистр, кириллица, `.exe` с расширением и без, папки с точками — работают; ведущие пробелы и `Steam.lnk` — нет (F-13).
- GUI: ↑/↓ меняют порядок и выбор корректно; «Убрать из группы» удаляет выбранные; удаление средней/единственной группы переносит значки в «Прочее».
- Рамки при плотной упаковке не перекрываются: горизонтальный зазор 52 px, вертикальный — 76 px; перекрываются только длинные подписи (F-12).
- Проверка автоупорядочивания через `FFlags` есть; бэкап позиций перед применением создаётся.
- Кодировки основных файлов кода и `README.md` — UTF-8 с BOM; `docs/review/*.md` (включая этот отчёт) — UTF-8 без BOM; `.cmd` — без BOM (F-26).
